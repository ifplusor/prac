# Agent 理论基础

> **本文档定义 LLM-based Agent 的通用理论基础，适用于所有 Agent 架构设计。**

## LLM 的固有特征与限制

| 特征/限制                | 影响                                              |
| ------------------------ | ------------------------------------------------- |
| API 无状态               | 每次调用都是全新开始，无法保留会话间的状态        |
| 上下文窗口限制           | 长上下文中性能下降，需要精心管理注入内容          |
| 擅长 In-Context Learning | 可以从少量示例中快速学习模式                      |
| 知识滞后性               | 训练数据有截止日期，无法获取最新信息              |
| 幻觉（Hallucination）    | 会生成看似合理但实际错误的信息，需验证机制        |
| 工具使用能力             | 支持 Function Calling，但需精确的 schema 定义     |
| 序列生成限制             | 无法并行思考，复杂推理需要 Chain of Thought 引导  |
| 多目标处理能力弱         | 多个目标同时存在时注意力稀释，优先级管理能力差    |
| 长流程性能衰减           | 执行步骤越多，上下文污染和累积误差导致性能下降    |
| Token 消耗成本           | 每次调用都有成本，需优化 prompt 和输出长度        |
| 输出长度限制             | max_tokens 限制，大量代码生成需分批或使用 diff    |
| 数值计算能力弱           | 直接算术容易出错，需要代码执行或工具辅助          |
| 缺乏真实世界交互         | 不能直接访问文件/网络/数据库，必须通过工具代理    |
| 确定性不足               | 温度参数导致输出随机性，关键操作需低温度或验证    |
| 时间感知缺失             | 不知道当前时间，需显式注入上下文                  |
| 并发与速率限制           | API 调用受 RPM/TPM 限制，批量操作需排队或并发控制 |
| 输入格式敏感性           | Prompt 措辞、示例格式微小变化导致输出质量剧烈波动 |
| 跨语言能力差异           | 英文训练数据占优，中文等语言性能下降              |

## 核心隐喻

### 1. 失忆的时间旅行者（无状态性）

> **每次调用都是一次时间重启，Agent 醒来时一无所知，只能通过阅读笔记本（持久化存储）来了解之前发生了什么。**

**设计启示**：必须主动记录一切重要信息；持久化机制是 Agent 延续性的唯一保证。

### 2. 盲人摸象的侦探（上下文窗口限制）

> **Agent 像戴着窄视角护目镜的侦探，一次只能看到案卷的一部分。**

**设计启示**：精心选择注入的上下文；检索质量 > 检索数量；精准优于全面。

### 3. 清醒梦境中的建筑师（幻觉 + 推理能力）

> **Agent 在梦中构建世界，逻辑清晰但细节会虚构，需要在现实中验证。**

**设计启示**：生成结果必须通过执行验证；工具返回值 > LLM 陈述；构建「生成 → 执行 → 反馈」循环。

### 4. 无手的策划者（缺乏真实世界交互）

> **Agent 是一个被困在密室的军师，只能通过信使（工具）与外界互动。**

**设计启示**：工具系统是 Agent 的感官和四肢；工具能力决定行动边界；所有外部操作必须代理。

### 5. 昂贵的顾问（Token 成本）

> **每次咨询都按字收费，冗余对话会破产。**

**设计启示**：优化信息密度；Diff > 全量替换；缓存 > 重新生成；工具链 > 多轮对话。

### 6. 注意力分散的多任务者（多目标处理）

> **LLM 不擅长在"脑子里"同时优化多个相互冲突的目标，长上下文中间部分容易被忽略。**

**设计启示**：多目标任务需显式拆分和优先级管理；使用外部追踪（Todo list）；独立子任务 > 全局优化。

### 7. 越走越累的长跑者（长流程衰减）

> **执行步骤越多，上下文污染、累积误差、目标漂移会导致性能指数级下降。**

**设计启示**：分段执行 + 状态压缩；周期性重新规划；子任务委托（Sub-agent）；单实例流程 < 15 步。

**长流程性能衰减的机制**：

- **上下文污染**：每步执行结果累积，噪音与信号比例恶化
- **累积误差**：单步 95% 准确率，10 步后降至 ~60%（0.95^10）
- **目标漂移**：原始目标在长流程中逐渐模糊
- **决策疲劳**：后期步骤倾向于"简单路径"而非"正确路径"

**经验阈值**（粗略估计，需根据实际场景调整）：

- 1-3 步：直接执行
- 4-8 步：Plan tracking + 中间验证
- 9-15 步：分段执行 + 状态压缩
- 16+ 步：**强制拆分**为多个子任务/子 Agent

## 架构推论

基于上述特征和隐喻，任何实用的 Agent 架构都必须具备：

### 基础能力（针对单一限制）

| 能力模块           | 对应LLM限制      | 实现方式                                                                      |
| ------------------ | ---------------- | ----------------------------------------------------------------------------- |
| **持久化记忆系统** | 无状态性         | 语义/情节/程序三层记忆（见 [memory_architecture.md](memory_architecture.md)） |
| **智能检索系统**   | 上下文窗口限制   | RAG、向量搜索、关键词检索                                                     |
| **验证反馈机制**   | 幻觉倾向         | 执行测试、错误处理、结果验证                                                  |
| **工具抽象层**     | 缺乏真实世界交互 | ToolProvider 协议、工具注册机制                                               |
| **成本优化策略**   | Token 消耗       | 批处理、Diff、缓存、懒加载                                                    |

### 高级能力（综合多个基础能力）

| 能力模块         | 依赖的基础能力                   | 实现方式                                                     |
| ---------------- | -------------------------------- | ------------------------------------------------------------ |
| **任务编排系统** | 持久化记忆 + 验证反馈            | Plan-then-Execute、Todo tracking、Sub-agent 委托、优先级管理 |
| **执行控制系统** | 智能检索 + 验证反馈              | 状态压缩、Checkpoint/Resume、中间验证、错误恢复              |
| **自我演化系统** | 持久化记忆 + 验证反馈 + 工具抽象 | 反思循环、策略沉淀、经验复用、自举迭代                       |
