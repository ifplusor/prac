# Agent Note: UI resource model — CRD / CR for view and view group

> **这是哪件工作**：prac UI 的声明式资源机制。它定义 core 的 CRD-lite：`ResourceDefinition` / `ResourceDeclaration` / registry / materializer。
> **关系**：UI umbrella 见 [2026-10-20-ui-framework.md](../in-progress/2026-10-20-ui-framework.md)；VS Code adaptor 见 [2026-10-17-vscode-host-architecture.md](../in-progress/2026-10-17-vscode-host-architecture.md)；container context 见 [2026-10-22-vscode-container-context.md](2026-10-22-vscode-container-context.md)。

## Summary

prac core 只提供 **CRD-lite 机制**：

- `ResourceDefinition<TSpec, TMaterialized>`：类型 / schema / validation / factory；
- `ResourceDeclaration<TSpec>`：`apiVersion` + `kind` + `metadata` + `spec`；
- `ResourceRegistry`：`(apiVersion, kind) → definition`；
- `ResourceMaterializer`：declaration → definition → materialized runtime。

source adapter 注册具体 CRD，例如：

- `VscodeViewGroupDefinition` / `VscodeViewGroup`
- `VscodeViewDefinition` / `VscodeView`

frame / arrangement 只认 core 的 `ResourceDefinition` / `ResourceDeclaration`，不认 `vscode`。

## Motivation

UI 的跨来源组合需要一个声明层：

- source 只声明“我贡献什么”，不决定 prac 的 placement；
- frame 不需要为每个 source 写分支；
- 新 source / 新 kind 通过 definition 注册，而不是改 frame；
- view / view group 可以有稳定的类型 / 实例边界；
- `kind` / `spec` 的分离让身份和配置不混。

CRD 只是借这个边界，不是把 Kubernetes 控制器框架搬进 prac。

## 1. 机制

```ts
interface ResourceDeclaration<TSpec> {
  apiVersion: string;
  kind: string;
  metadata: {
    id: string;
    labels?: Record<string, string>;
    annotations?: Record<string, string>;
  };
  spec: TSpec;
}

interface ResourceDefinition<TSpec, TMaterialized> {
  apiVersion: string;
  kind: string;
  validate(spec: unknown): TSpec;
  default(spec: unknown): TSpec;
  materialize(
    decl: ResourceDeclaration<TSpec>,
    ctx: MaterializeContext
  ): TMaterialized;
}
```

- `apiVersion + kind` 是类型，声明时确定、不可变；
- `metadata.id` 是身份；
- `spec` 是可变配置；
- `Definition = 类型 / CRD`；
- `Declaration = 实例 / CR`；
- kind 改变 = 新 CR / 迁移，不是改字段。

`ResourceRegistry` 与 `ResourceMaterializer` 是普通服务，不是 controller framework：

```text
source adapter
  ├─ register Definition
  └─ emit Declaration
        → Registry
          → Materializer
            → runtime
```

## 2. 资源

第一版只有两类资源：

| 资源 | kind | spec 子类型 |
| --- | --- | --- |
| **view group** | `ViewGroup` | `spec.groupKind: container \| editor` |
| **view** | `View` | `spec.hostKind: react \| view-pane \| editor-pane \| slot \| opaque` |

具体 CRD 由 source adapter 注册：

- `VscodeViewGroupDefinition` → `VscodeViewGroup`
- `VscodeViewDefinition` → `VscodeView`

`VscodeViewGroup` materialize：

```text
VscodeViewGroup
  → ViewGroupState
    → ViewGroup
      → binding?（ContainerBinding / EditorGroupBinding）
```

`VscodeView` materialize：

```text
VscodeView
  → View
    → VscodeViewHost
      → ViewPane / EditorPane
```

- `ViewGroupDefinition` 不是 group runtime；
- `ViewDefinition` 不是 view runtime；
- `ViewGroup` / `View` 是 materialized runtime；
- `binding` / `host` 是 runtime，不持久化。

## 3. 复杂度预算

| 保留 | 不做 |
| --- | --- |
| 2 类资源：`ViewGroup` / `View` | 通用 resource framework |
| 1 个 CR 信封 | 任意 UI 概念都做 CRD |
| 1 个 definition registry（`Map`） | API server / etcd / watch / informer |
| 1 个 materializer | controller / operator / reconcile loop 框架 |
| `validate` / `default` / factory 函数 | JSON Schema / admission webhook / conversion webhook |
| 一个 declared group 最多一个 binding | 多 binding / attachment 层 |
| 一个 view 一个 view host | `status` / conditions / finalizers / ownerReferences |

- **只有 view 和 view group 是 CR**；action / overlay / part / host 仍走 contribution 模型。
- **不按 view 类型细拆 CRD**：tree / webview / React 用 `spec` / `hostKind` 表达。
- **一个 group 只有一个 declaration 来源**；不做多 source 合并 group kind。
- **第一版不做多版本转换**；只保留 `apiVersion` 字段。
- **kind 不可变**；要变 kind，新建 CR / 迁移。

## 4. 生命周期

- **正常启动**：source 注册 definition，产生 declaration；materializer 产出 runtime；placement 由 frame 决定。
- **recovery**：definition / declaration 由 source 重建；materialized runtime 不持久化；layout / `ContainerRecord` 从 layout store 恢复。
- **动态安装**：新 definition / declaration 进入 registry；materialize。
- **卸载 / reload**：declaration 消失；runtime 释放；placement 可 tombstone。
- **不根据 group 内容推断 kind**；kind 来自 declaration。

## 5. Open questions

1. **registry / materializer API**：definition 注册是同步还是异步；materialize 是否允许异步 factory。
2. **schema / validation**：只用 TypeScript 函数，还是需要可序列化 schema。
3. **版本**：`apiVersion` 是否做多版本转换；第一版不做，何时需要。
4. **拆 CRD**：`ViewGroup` 的 container / editor 是否最终拆成两条 CRD；`View` 是否按 host 行为拆。
5. **持久化**：哪些 materialized 结果进 layout store；`ContainerRecord` 是否唯一持久化记录。
6. **隔离**：definition / factory 失败是否只影响自己的 CR。
