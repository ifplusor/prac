# Agent Note: stack 的行为定义

## Problem

一个区域可以**同时显示多条视图**（`stack` 模式），纵向排列，每条一行。这个"栈"是 prac 自己加的（VS Code 把"多条视图上下排"实现为一个纵向的 `SplitView`，没有"栈"这个概念）。它的行为一直被分散地定：有些写在 layout note 的设计里，有些只存在于实现里，还有几处**互相冲突**——于是同一个动作在不同路径上给出不同结果（现场见过"布局里存 69、屏幕上画 519"）。

这份 note 只做一件事：**把栈的行为完整、可验证地定义下来**。先定行为，再选实现。

## 行为定义

按"人能观察到什么"写；每条都应当能被判据钉住。**总则：凡未写明处，一律对齐 VS Code**（`SplitView` / `Grid`）；VS Code 怎么做，这里就怎么写。

### A. 构成

- **A1** 一个区域是否成栈，由区域名绑定决定（`stack: true`）。**只有可见视图 ≥2 时才真的成栈**；正好 1 条时**裸渲染**（无标题、无手柄）。
- **A2** 成栈时每条一行、同时可见；顺序 = 该区域的视图顺序。
- **A3** 每条有标题条（标题 + 折叠开关）与内容盒。
- **A4** **`hidden` 不是折叠**：隐藏的视图**不成行**（A2 的"每条"只指可见视图）。它在记录里的位置归约到所在区域的 id（stack 的列分栏 id），成形函数把它的 leaf 摘掉（摘之前把 leaf 的 `size` / `collapsed` / `cachedSize` 写回记录，和融回区域同一条规则）；`show` 后按它的 `order` 重新成行。折叠（E）则是留在行里的标题，两者不是一回事。

### B. 边界与手柄（对齐 `updateSashEnablement`）

- **B1** 行与行之间有**边界**（一条 sash 的位置 = 上面那条的底边）。
- **B2** **可拖的方向**：向下/右（正 delta）需要**上方还能长**（`max − size > 0`）且**下方还能缩**（`size − min > 0`）；向上/左（负 delta）需要**上方还能缩**且**下方还能长**。两侧都是**累计**判断：从边界往一侧看，只要**某一处**还能动，那一侧就算能动；折叠行跳过（B3）。**至少一个方向可拖 ⇒ 这条边界可拖**；两个方向都不可 ⇒ 见 B4。
- **B3** **折叠的行不能缩也不能长**（它的 `size` 不是高度：折叠时 `size = 0`、记忆在 `cachedSize`，见 E1；没有余量）⇒ 求高度时**跳过它**，继续向该侧找**展开的**行——"sash 邻着折叠的行，会继续向上下的展开的行求高度"。
- **B4** **边界的四个状态**（对齐 `updateSashEnablement` / `SashState`）：`Enabled` 两个方向都能拖；`AtMinimum` 只能向下/右（正 delta）；`AtMaximum` 只能向上/左（负 delta）；`Disabled` 两个方向都不可拖。**只有 `Disabled` 没有视觉**（`pointer-events: none`、`cursor: default`、无 hover）；`AtMinimum`/`AtMaximum` 仍有方向光标和 hover，能单向拖。**整侧（从边界到区域边缘）连续折叠且贴顶/贴底** ⇒ 那一侧没有任何能动的展开行 ⇒ 两个方向都不可 ⇒ `Disabled`；若只是某个方向没有余量（不是整侧折叠），是 `AtMinimum`/`AtMaximum`，不是 `Disabled`。拖动只从非 `Disabled` 的边界开始；`Disabled` 不启动拖动。
- **B5** **双击一条边界 = reset**（VS Code `onDidReset`，`splitview.ts:1186`）。双击不是拖动，不受 B4 的可拖标记限制。VS Code 找的是边界两侧**最近的可见 snap 行**（`findFirstSnapIndex` 第一遍跳过隐藏行，`:1454-1461`）；只有被选中的那一行本身隐藏时，`onDidReset` 才直接返回（`:1193-1199`）——一个折叠行不挡住外侧的可见行。prac 的 reset 消费者**不依赖 `IView.snap`**：把 stack 的所有行都当候选（行本身就是可折叠的标题），向外跳过折叠行、取最近的一对展开行；整侧都折叠时没有 pair。reset 到什么由消费者决定（workbench 那一层不在这棵源码树里）。
- **B6** **拖 sash 期间按住 Alt**：对齐 `onSashStart` / `onSashChange` 的 alt 分支——跳过 `snap`（本 stack 已不启用 `snap`）；`minDelta` / `maxDelta` 取**相邻视图的半幅**（最后一条边界取**上方那条（被拖行）**的 `(min − size)/2` / `(max − size)/2`，其余取**下方那条**的 `(size − max)/2` / `(size − min)/2`）；`inverseAltBehavior` 默认 false；**Alt 只改高度，不改变折叠态**。上游用 body 级 `keydown` / `keyup` 达到同一效果（`:894–963`）；prac 只承诺行为，不承诺监听方式。不是取消，也不适用于重排那条手势。
- **B7** **可拖的边界**（包括 `AtMinimum`/`AtMaximum` 的单向情况）的手柄可点区域 = 边界的 ±`SASH_SIZE`；sash 本身是**绝对定位 overlay**，不占 flex 空间、默认透明，只在 hover/active 时显示；只有 **`Disabled`** 的边界没有手柄/光标；**最后一条没有边界**（它的底边就是区域的边）。

### 术语：sash 与 snap

- **sash** 是那条**可拖的边界**（分隔条）：VS Code 的 `Sash`（`sash.ts` / `sash.css`，4px），落在两个视图之间；拖它改尺寸，双击 reset（B5），`updateSashEnablement` 给它 `Enabled` / `AtMinimum` / `AtMaximum` / `Disabled`。prac 的 stack 里，它对应行与行之间的 4px 边界（`Sash` 组件本身，绝对定位 overlay；B7）。
- **snap** 是**拖动 sash 时的一个可选行为**，不是第二个手势、也不是另一个元素：视图声明 `IView.snap: true` 时，拖 sash 把它推过阈值（`minDelta ± half(minimumSize)`，带滞回）就把它**隐藏**（`setVisible(false)`），拖回可以再**显示**；默认 false，目前 workbench 的 viewlet stack 没有声明它；Alt 拖会关掉 snap。
- **prac 的 stack 不启用 `snap`**（对齐 Explorer viewlet stack）：拖 sash 只改高度，不折叠、不展开；折叠只由标题开关完成（D3–D5）。代码里旧的 `dragSnapTarget` / `dragChainTarget` 是 prac 先前的 drag-fold，已不在这份行为定义里。`snap` 这个词只用于 VS Code 的 `IView.snap` / B5 的 reset 对照；prac 的 stack 不用它。折叠行相邻的边界仍可拖：锚点是边界**上方最近的未折叠行**（折叠行是标题，自己不改高度，会随边界移动）；中间的折叠视图不会让整条边界失效。拖动开始时把每条**展开行**的绘制高度播种到树里（C8 的比例分配在“主张之和 = 内容”时是恒等）；否则未参与当帧写入的旧主张会被重新拟合，表现为上下展开视图的弹性抖动。
- **注意**：note 的“离场与回归（第 3 步）”讲的是**区域块**的 `snap`（`snap: true` 的块拖到边缘离场/回归），不是 stack 行；stack 行不启用 snap（D3–D5 只改高度）。

### C. 高度

- **C1** 默认**等分**可用高度。
- **C2** 人拖过之后，那一条的高度**就是它自己的**：屏幕上是它，刷新后仍是它。
- **C3** 每条有**下界**（`MIN_ENTRY = 48`：标题 + 一点内容）与**上界**（见 C6）。
- **C4** 折叠的条目占**标题高**（`HEADER_HEIGHT = 20`）。
- **C5** 拖动按 B2/B3 的方向取高度（对齐 `SplitView.resize`）：**增长量**按边界**上方**（含被拖那条）由近到远给，**让出量**按**下方**由近到远取；每条到自己的上/下界为止，再给下一条。反向拖动同理。
- **C6** **余量不按比例**：`distributeEmptySpace` 把**余量整块给一个行**，到它的 `maximumSize` 为止。**上界由行自己声明**（`IView.maximumWidth/maximumHeight`，`splitview.ts:60`；隐藏时记作 0，`:254-255`；不声明就无上限）——没有上界就会一条吞掉全部（现场见过 `openEditors` 从 69 被画成 519）。grid 那条 note 里的 per-region `max` 与本条一致。
- **C7** 人设的高度加起来**超过**区域高度时：按 C6 的顺序收敛，且**任何一条不破下界**。
- **C8** **区域自身变高/变矮时**（窗口变化、邻居让位）：对齐 `SplitView.layout`——有 `proportions` 时（初始/拖动后 `saveProportions`；`proportionalLayout` 默认 true）按各自持有的比例分配，并 `clamp` 到 `min`/`max`；分完的余量再按 C6（`distributeEmptySpace`，不按比例）。没有 `proportions` 时走 C5/C6 的 resize 规则。

### D. 拖动的手势

- **D1** 一次拖动以**开始时的快照**为基准（不跨帧累积）。
- **D2** 松手后：屏幕上的值**成为**该条的高度（"屏幕 = 状态"）；整栈逐条写回——不只被拖那条，邻居被重新分配后的高度也要落进状态，否则刷新后它们会按旧主张漂移；**折叠行不写 `size`**（J3），它的记忆已在 `cachedSize`。
- **D3** **拖动到行下界就停，不折叠**（VS Code 的 Explorer viewlet stack 不启用 `snap`）：边界拖到 `MIN_ENTRY` 就停住，行仍是展开的标题 + 内容；折叠只由标题开关（E）。
- **D4** **没有连续折叠链**：一次拖动只改高度，不折任何行；不存在“拖过一条再折下一条”。
- **D5** **拖动永不改变折叠态**：既不折、也不展；折叠/展开只由标题开关改变。

### E. 折叠与展开

- **E1** 折叠 = 只剩标题；它的高度**被记住**（对齐 VS Code ：`size` 与 `_cachedVisibleSize` 是**两个字段**——隐藏时 `size = 0`、记忆写进 `_cachedVisibleSize`，`splitview.ts:228-246`）。记忆的值**由调用者决定**：可以显式传入，缺省取当时的高度（`:237`）；拖动路径上传的是**拖动开始时的快照值**（`resize` 的 `sizes` 参数，`:1015`）。prac 的行在折叠时 `size = 0`、`cachedSize` 记高度；**画出来的 20px 标题不是 `size`**（C4），由 frame/分配器按 `folded` 给 `HEADER_HEIGHT`。J3 因此成立：折叠的行不被写一个"高度"。
- **E2** 展开 ⇒ 回到**记住的高度**，并按 `clamp(cached, view.min, view.max)` 收敛（`:234`）——即**不足下界会被抬到下界**，不是丢弃。
- **E3** 记忆**参与持久化**：序列化状态里带 `cachedVisibleSize`（`:273` / `:277`），grid 的 leaf 也带 `size` 与 `visible`（`grid.ts:756-761`）⇒ 折叠的行**刷新后仍记得它原来多高**。
- **E4** 折叠/展开腾出或需要的空间，走 C5/C6 的规则（给还能长的行、到上界为止、**不按比例**）。

### F. 顺序与重排

**两种手势按"地点"分开**（已定）：**拖 sash（= 行的底边 5px）= 只改高度**；**拖标题条 = 重排顺序**。它们互不触发：改高度走 B/C/D 的 resize，重排**不折叠、不展开**任何行。

**移动的模型**对齐 VS Code `Grid`：给定**参照行 + 方向**（上/下）即可确定落点（`moveView(view, sizing, referenceView, direction)`，`grid.ts:480-495`；方向 `Direction.Up/Down`，`editorPart.ts:807-810`）。拖动标题时，落点提示落在某条边界上（= 参照行 + 方向）。同一父节点内是**纯换序**；被移动的视图**保持自己的尺寸**（不传 `Sizing` 时不做重新分配）。

- **F1** 顺序 = 该区域的视图顺序。
- **F2** **抓手 = 标题条**（标题文字与折叠开关之外的可拖区域）；**行底边的 `SASH_SIZE` 属于 sash**，在那里按下是改高度，不是重排。
- **F2b** 标题条同时回答两种手势：**点**（按下到抬起没有明显移动）⇒ **折叠/展开**；**拖**（移动超过阈值）⇒ 重排。这样"点标题折叠"这个习惯不会被拖拽吃掉，折叠开关（箭头按钮）也仍在。
- **F3** **折叠的行也能被拖**（它就是一个标题条）。
- **F4** 拖动**只改顺序**：**每条的高度跟着它自己走**，折叠态也跟它自己走（都不留在槽位上）。
- **F5** 重排**不折叠、不展开**任何行（不触发 B/C/D 的 resize）。
- **F6** 范围是**同一区域内**；把视图搬到别的区域走既有的"在区域之间搬视图"。
- **F7** `tabs` 模式下同一份顺序就是 **tab 的顺序**；重排同样成立（顺序是区域级的，两种模式共用）。**表示有两个形态**：stack 的顺序住在分栏孩子的顺序里，tabs 的条序住在 `ViewRecord.order` 里；它们是同一份区域顺序的两个形态，任何重排都必须同步另一份（否则切模式会漂）。
- **F8** 拖动被丢到区域外 ⇒ **回到原位**，不留改动。**没有 Esc 取消手势**（对齐 VS Code：它的拖动没有任何按键取消——`splitview.ts:894` 的 body 级监听只服务"按住 Alt 拖 sash"，DnD 那一层也没有 Escape）。
- **F9** 重排后的顺序随布局持久化。

**VS Code 对照**：`Grid` **没有内置拖拽**（`gridview.ts` 里没有 `dragAndDrop` / `dropTarget`），移动是程序化的；拖拽手势在更高层（编辑器的 tab DnD、侧栏的 viewlet DnD），那两处不在这棵裁剪过的源码树里 ⇒ 抓手与落点的具体形态是**prac 自己的决定**。

### G. 与「选择（tab）」的关系

- **G1** `stack` 与 `tabs` 是**同一批视图的两种模式**（由区域名绑定）。在 `tabs` 下同时只显示一个 ⇒ **没有高度语义**：该模式里各视图的 `size` **不生效**。

### H. 退化情形

- **H1** 0 条：区域不渲染（空区域不渲染）。
- **H2** 1 条：裸渲染。
- **H3** **全部折叠**：没有人能长 ⇒ 腾出的空间**留白**（推导自 B2/B4：此时所有边界都禁用）。这条是**从 VS Code 规则推导**的，不是直接观察。

### I. 持久化

- **I1** 每条的高度（含折叠行的记忆高度）、折叠态、顺序都随布局持久化。
- **I2** 刷新后：**所见即所存**。

### J. 明确不做的

- **J1** 拖动**不**从"不能动的那一侧"借空间（那一侧要么是折叠的行、要么已经在它的下界）。
- **J2** 折叠**不**被拖动自动打开。
- **J3** 折叠的条目**不**被写尺寸（它是标题，不是"这么高"）。
- **J4** **余量**分配不按比例（C6）；区域整体 resize 按 C8 的 proportions。
- **J5** **标题条没有双击手势**（双击标题条不折叠、不重排）。
- **J6** **没有键盘路径**（不做 Alt+↑/↓ 之类的重排快捷键）。

## 必须先裁的

1. ~~行的上界给多少~~ —— **已定（对齐 VS Code ）**：**VS Code 的答案已经明确——`max` 由每个视图自己声明，框架只读不发明**（`IView.maximumWidth/maximumHeight`，`splitview.ts:60`；`SplitView` 只读 `view.maximumSize`，`grid`/`splitview` 里的 `distributeEmptySpace` 用它封顶）。三条配套事实：
   - **隐藏的视图，`maximumSize` 记作 0**（`get maximumSize() { return this.visible ? this.view.maximumSize : 0; }`，`splitview.ts:254-255`）⇒ 折叠的行**不可能再长大**，这正是"邻着折叠行就继续找展开的行"的基础；
   - **多数视图不设上限**（`Number.POSITIVE_INFINITY`）⇒ 空闲空间会**整块给第一个还有余量的行**（"一条吃掉"是 VS Code 行为，不是异常）；

   ⇒ 所以对 prac 决定已下：**prac 的行先都不声明 `max`**。对齐 VS Code （侧栏 viewlet 的形态）就是**不设上限**；若要有上限，也应由**视图自己声明**，而不是框架按比例拍一个。
2. ~~顺序怎么表示~~ —— S2 已定：stack 的顺序 = 分栏孩子的顺序；tabs 的条序仍存在 `ViewRecord.order`。F7 要求两者是同一份区域顺序，重排时同步（`moveEntry` 与 `reorderTab` 都要写另一份）。
3. ~~折录取哪一刻的高度~~ —— **已定**：对齐 VS Code （调用者可显式传入、缺省取当时高度；拖动路径传拖动开始时的快照），见 E1–E3。

## 实现选型（已裁：S2）

**栈 = 一个纵向分栏**：每条 = 一个只住一个视图的 **region（leaf）**。高度只住在树里（leaf 的 `size`）；
`ViewRecord.size` **不再是行高度**（`tabs` 模式本就没有高度语义，见 G1；它只在尚未成行/单视图时暂存声明与记忆，见"融回区域"）。

落地分四步，每步的行为验收写在下面：

1. **栈 → 叶子**：`stack: true` 的区域改成"一个 `column` 分栏，孩子是各条视图的 leaf"。
   验收：**行为不变** —— `verify:stack` 的三件事照旧；`rows == sizes`；刷新后一致。
2. **补语义**：块（区域与叶子）的 `min` / `max` / `priority`，以及边界的 `Sizing`。
   验收：同轴三块拖一条边 ⇒ 三块按比例变、任一块不破 `min` / `max`、另一轴纹丝不动；
   窗口变紧时**中心先让位**（`High` 先被缩，`Low` 保住尺寸——见下）。
3. **手势对齐**：把边界拖到边缘 ⇒ 该块**离场**（`visible = false`，尺寸记住），空间按 `Distribute` 分出去；
   拖回 ⇒ 它带着记住的尺寸回来并继续跟随拖动；双击 ⇒ 同轴平分（邻居已离场时不动）。
4. **（可选，另裁）** 借上游 `Grid` 作引擎：那时模型已同形，成本小得多。

### 离场与回归（第 3 步）

**拖动可以把一块送走**：`snap: true` 的块在"按这一拖算下来会剩下不到**自己最小的一半**"时离场 ✓，拖回超过这条线就回来 ✓ —— 两条线之间隔着自己的 `min`，这就是**滞回**，它让边界不会在阈值上来回跳 ✓（邻居到最小、这一拖本来走不动时，也同样会把它送走：这是"你已经在挤它了"的直译 ✓）。

**离场是 `collapsed`，不是删除**：块留在树里、`size` 为 0、`cachedSize` 记住**拖动开始时**的尺寸（VS Code 的 `snapBefore.size` ✓）——`visible = false` 在 prac 里的写法就是这个（0 尺寸但仍在场 ✓）。因此它的 sash 还在，同一个手势就能把它拖回来 ✓；回来时先恢复记住的尺寸，**并继续跟随这一拖**（VS Code 也是拿同一个 delta 再跑一次 resize ✓）。

**双击**：这一侧若有块已离场 ⇒ **什么都不做**（VS Code `splitview.ts:1193-1199` ✓）；否则同轴各块**平分**（VS Code `grid.ts:714-753` 的最后一条答案：优先用块自己声明的尺寸，没有就 `distributeViewSizes` ✓）。**按住 Alt** 拖动 ⇒ 关闭吸附（VS Code `:929` ✓）。

**`setViewVisible` 的分配**：藏掉一个块里**最后一条可见视图** ⇒ 该块不再渲染 ✓，它的空间按 `Distribute` 落到兄弟身上 ✓；再显示 ⇒ 回来 ✓。这条不需要新语义——不渲染的块本来就不占空间 ✓，需要的是**确认行为**（门的第 4 组 ✓）。


### 栈只有一条路（落地形态）

高度住在树里之后，**栈的分配也只有一条路**：`allocateStack`（树版）看"每条的 `size` 是主张、`folded` 是标题"来给高度，而**画面严格照分配画**——一条行的样式是 `0 0 <分配到的 px>`。区域变高/变矮时按 C8：有 `proportions` 时按各自持有的比例分配并 `clamp` 到 `min`/`max`；分完的余量才按 C6 整块给一条（从最后一条往前找还能动的那条），全部折叠时谁也不动、多出来的就是留白（H3）。旧形状的那套"按视图记录分配"已经拆除，所以不会再有"两个权威"。

**边界的可用性也写在树里**（B2/B4）：按 `updateSashEnablement` 的累计方向判断——`Enabled` 两个方向可拖；`AtMinimum`/`AtMaximum` 只有单向可拖（仍有方向光标和 hover）；只有两个方向都不可（**整侧连续折叠且贴顶/贴底**、末行、或两侧都没有余量）才是 `Disabled`，**没有光标/手柄/悬停**。拖动从非 `Disabled` 的边界开始；拖动只改高度，不折叠、不展开（D3–D5）。按住 **Alt** 拖 ⇒ 只改高度、按 B6 的 alt 分支改 clamp、**不改变折叠态**；双击 ⇒ 向外越过折叠行找一对来平分，整侧折叠就**什么都不做**（B5；双击不是拖动，不受 `Disabled` 限制）。


### 尺寸的语义（第 2 步）

**边界只由树决定**。一次拖动把"边界两侧"都算进去：`up` 是边界之前的孩子（近的在前），`down` 是之后的孩子，各自按 `priority` 排序（`high` 先被考虑、`low` 最后）；拖动量先收敛到两侧**真正能让的**（长出的一侧受 `max` 限，缩进的一侧受 `min` 限），再按 `Sizing` 分：

- **`distribute`**（默认，VS Code `DistributeSizing`）：整个侧边**按各自持有的比例**吸收，某个到界就把余量传给下一个；
- **`expand`**：只推最近的邻居（VS Code `SplitView.resize`）。

**静止时的分配**同理：固定块取自己的 `size`（收敛到 `min`/`max`），余量给柔性块——按各自持有的尺寸成比例，谁都没有尺寸（刚分出来的兄弟）则**等分**；不够时按 `priority` 收回（`high` 先让、`low` 最后），并且**下界是承诺**：低于 `min` 的会被抬回去，房间从有余量的兄弟那里取。

**`priority` 的值照抄 VS Code 的部件**：中心（编辑区）`high`、左右轨与底栏 `low`（`editorPart.ts` / `sidebarPart.ts`）。因此窗口变小时**中心先让位、轨道保住尺寸**——`High` 的含义是"先被 resize"，两个方向都如此。

**`Sizing` 是拖动的选择，不是块的性质**：同一条边界可以按两种语义拖；默认取 `distribute`。模型两个都实现，帧用默认值。

**拖动从像素出发**：树里的 `size` 只是"主张"，没人拖过的柔性块主张 0，所以拖动必须以**画面上的实际尺寸**为起点（帧在按下时读出来，交给模型）；写完的尺寸回到树里，柔性块继续按它成比例分摊。


### 第 1 步的状态形状（栈 → 叶子）

**不变量**：一个 `stack` 模式的区域里有 **≥2 条可见视图**时，树里就是**一个 `column` 分栏**，孩子是**一视图一个 region**（leaf），每条**可见**视图的 `ViewRecord.region` 指向各自的 leaf；隐藏的视图不成行（A4），它的记录归约到分栏 id。

| 事实 | 之前 | 之后 |
| --- | --- | --- |
| 条目的高度 | `ViewRecord.size`（+ `cachedSize`）| **leaf 的 `size`**（树节点）|
| 折叠 | `ViewRecord.collapsed` + `size` | **leaf 的 `collapsed` / `cachedSize`**（行内）；融回区域/未成行时回到 `ViewRecord` |
| 顺序 | `ViewRecord.order` | **分栏孩子的顺序**（leaf 的顺序）；tabs 的条序仍是 `ViewRecord.order`，重排时两份同步（F7）|
| 谁算高度 | 渲染期 `allocateStack` | 布局期 `resolveSizes`（一次算完）|
| `ViewRecord.size` | 存高度 | **不再是行高度**（行内高度只在 leaf；单视图/未成行时才在这里暂存，见下）|

**融回区域不是丢状态**：一条 stack 融回一个区域时，把它的行 `size` / `collapsed` / `cachedSize` 写回该视图的记录（同一个持久化键）；重新成栈时从记录搬回 leaf。区域自身的 `collapsed` 是**轨道折叠**，不表示一条视图的折叠。`ViewRecord.size` 因此不是行高度的第二权威——行内高度只在 leaf。

**成形与迁移是同一个函数**：每次状态变化后，把"住着 ≥2 条可见视图的 `stack` 区域"整理成上面的形状（`ensureStackShape`）——按顺序把每条**可见**视图各放进一个 leaf、把视图记录里的高度与折叠搬进 leaf、把这些 leaf 挂进一个 `column` 分栏。旧数据（`prac-layout/v1`，数据由人清）加载后跑同一个函数即完成迁移，所以**不需要单独的迁移代码**。

**只有栈改形状**：只住一条视图的区域、以及 `tabs` 模式（一个区域住多条视图、只显示一条）都不变 ⇒ 迁移是局部的。

**这一条的手势**：不重写，仍然是现有的拖边界 / 双击复位 / Alt，只是它们写的是 **leaf 的尺寸**而不是视图记录 —— 行为因此不变；把它们推广到"区域的 sash"（含 `Distribute` 语义）留给第 2、3 步。

### 寻址：id 命名的是"一个位置"，不是"一种节点"

分栏**继承它取代的那个区域的 id**。因此 id 的含义是"这个位置"，区域与分栏都是它的形态。凡按 id 找位置的地方都按"区域**或**分栏"回答（`findNode`）；凡把一个视图的位置当成区域来用的操作，都先归约到**结构区域**（`structuralRegion`：视图住在行里时，行代表的是占有该 id 的那个分栏）——`splitView` 因此把新窗格放在**整个栈的旁边**，而不是两条行之间。放置的目标同理：`place`/`placeQuietly` 的 id 若是 entry leaf，归约到它所属的 stack（在那里成行/换序），不把第二个视图塞进一个 leaf；对外列出的"可移动位置"也按位置归约——stack 只出现一次，不把内部 leaf 当目的地。

### 不变量在**每次写入**时成立

`ensureStackShape` 是唯一的成形函数，包在 store 的每一次写入外：任何时刻被观察到的状态都满足上面的不变量——放置、折叠、隐藏、移除都不例外。它同时完成三件收尾：

- **≥2 条可见 ⇒ 分栏**；**一条 ⇒ 融回区域**（一条视图没有标题，高度/折叠写回记录）；**一条不剩 ⇒ 不再占位**（残留若是柔性的，`isPresent` 会当它"在场"，空底栏就赖着不走）；**隐藏/移除的视图不成行**（A4，leaf 被摘掉）；
- 旧式记录里残留的高度/折叠（`ViewRecord.size` / `cachedSize` / `collapsed`）被**搬进**它所在的 leaf（同一个持久化键，没有迁移步骤）；**融回区域时反向搬回**（见"融回区域不是丢状态"）；
- 分栏**继承区域的基准**（`size` / `flex`）：栈站在原来那条固定宽度的轨道上时，宽度不变；`size` 为 0 表示"没有主张"（容器层的孩子就是这样），那就填满。


**验收（行为不变）**：

- `verify:stack` 的三件事照旧（一条裸渲染 / 两条成栈并折叠 / 折叠后展开回原高——header 点击与 `setViewCollapsed` 两条路径都要）；
- **边界按 B2/B4**：`Enabled` 双向；`AtMinimum`/`AtMaximum` 仍可单向拖、有方向光标；`Disabled`（整侧连续折叠且贴顶/贴底、末行、两侧都无余量）不可拖且没有光标/手柄/悬停；
- **C8**：区域变高/变矮时，有 `proportions` 的行按比例变、每行不破 `min`/`max`；分完的余量才按 C6 整块给一条；
- **`rows == sizes` 由构造成立**：画面来自 `resolveSizes`，拖动写的就是同一批数；
- 刷新后一致；
- 单测：`allocateStack` 的用例改为对**树的尺寸分配**断言；栈的手势用例（拖边界 / 双击复位 / Alt / B4 四态）改为对 **leaf** 断言。
