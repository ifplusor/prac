## 2. Editor（feature，只引用）

- editor 窗口的 content = VS Code 的 editor pane；editor group = VS Code 的模型投影（无 UI）；每窗口一个 input；`PracWindowInput` 是身份；
- 设计 / 投影 / 空组规则在 [tech-extension-vscode](./2026-11-05-tech-extension-vscode.md)；实现（per-window pane host、input 映射、记录表）在 `ui-vscode-editor`；
- **本文不再定义 editor host**：它是 editor 这个 window content 的实现，不是 IDE 能力面的一层；
- 打开入口（文件 / diff / custom editor / webview editor）属于 editor extension 的 contributes；prac 侧只看到 window + content。

## 3. Capability envelope

所有 IDE 能力统一成：

```ts
interface Capability<T, A> {
  snapshot(): T;
  subscribe(listener: () => void): () => void;
  settled(): Promise<void>;
  version(): number;
  readonly actions: A;
}
```

- `snapshot` 同步读；`settled` 等待异步源；`version` 单调；`subscribe` 变更通知。
- 数据只读；动作显式；不让 UI 直接改 VS Code 内部。
- **capability 是投影**，不是第二权威；状态仍在 VS Code。

## 4. Terminal

```ts
interface TerminalSession {
  id: string;              // stable
  title: string;
  cwd?: string;
  shell?: string;
  state: "starting" | "running" | "exited";
  exitCode?: number;
}

interface TerminalCapability
  extends Capability<readonly TerminalSession[], {
    create(opts?: { cwd?: string; shell?: string; title?: string }): string;
    close(id: string): void;
    write(id: string, data: string): void;
    resize(id: string, cols: number, rows: number): void;
  }> {
  onData(id: string, listener: (data: string) => void): () => void;
}
```

- **PTY 在 code server**；xterm 在 window；数据通过 capability / message channel。
- `create` 返回 session id；`close` 杀 PTY；`write` / `resize` 直接。
- **terminal 是 app window**：一个 terminal 一个 window；`ApplicationDefinition` id `terminal`，`multi`，`instanceKey = sessionId`。
- **agent terminal 是 DSH `terminal` 工具**，不走这个 capability；两者进程分开。
- **状态**：session 归 VS Code；prac 不复制 scrollback。
- **失败**：PTY 退出 → state exited；UI 显示 exitCode；可重开。
- **open**：terminal 是否 window / panel；多 terminal 的 identity；与 agent terminal 切换。

## 5. SCM

```ts
interface ScmRepository {
  id: string;
  root: string;
  branch?: string;
  changes: readonly ScmChange[];
}
interface ScmChange {
  path: string;
  status: "modified" | "added" | "deleted" | "renamed" | "untracked" | "conflict";
  staged: boolean;
}
interface ScmCapability
  extends Capability<readonly ScmRepository[], {
    stage(repo: string, paths: readonly string[]): void;
    unstage(repo: string, paths: readonly string[]): void;
    commit(repo: string, message: string): void;
    openDiff(repo: string, path: string): void;
  }> {}
```

- SCM view 是 **board widget**；diff 是 editor app window。
- 状态归 VS Code / git 扩展；prac 只读 + 动作。
- GitLens 的额外 view 走 catalog / widget；不特殊。
- agent git 走 DSH bash / 工具，不走 SCM capability。
- **open**：多仓库 / GitLens / conflict。

## 6. Search

```ts
interface SearchQuery {
  pattern: string;
  isRegex?: boolean;
  caseSensitive?: boolean;
  include?: string;
  exclude?: string;
}
interface SearchResult {
  resource: string;
  line: number;
  column: number;
  preview: string;
}
interface SearchCapability
  extends Capability<{ query?: SearchQuery; results: readonly SearchResult[]; done: boolean }, {
    search(query: SearchQuery): void;
    cancel(): void;
    open(resource: string, line: number, column: number): void;
    replace(query: SearchQuery, replacement: string): Promise<void>;
  }> {}
```

- search view 是 **board widget**；结果打开 editor。
- 查询流式；`cancel` 取消；`settled` 等结果。
- replace 走 VS Code 命令 / workspace edit；prac 不自己写文件。
- agent 搜索用 DSH `fs-search`；不共享。
- **open**：search editor / 多根 / 历史。

## 7. Problems / diagnostics

- 已有 `capabilities.diagnostics`：summary / page / query / subscribe / settled / version。
- problems view 是 **board widget**；点击 → editor。
- **read-only**；agent `lsp` 不读这份缓存。
- 迟到数据：`settled()` 后再当作真相；UI 显示 loading。
- **open**：severity / source 过滤；与 LSP push-only 的关系。

## 8. Output

```ts
interface OutputChannel {
  id: string; label: string;
}
interface OutputCapability
  extends Capability<readonly OutputChannel[], {
    show(id: string): void;
    clear(id: string): void;
  }> {
  onLine(id: string, listener: (line: string) => void): () => void;
}
```

- output 是 **board widget / panel**；channel 列表 + lines。
- 流式；背压 / 截断策略（open）；不把 output 当 telemetry。
- **open**：保留 / 清理；用户可见日志 UI。

## 9. Settings / keybindings

- settings / keybindings 是 **editor app window**；打开走 editor input / command。
- 不新增 capability；用 `runCommand("workbench.action.openSettings")` / keybindings。
- 作用域 / JSONC / 同步归 VS Code。
- **open**：prac 自己的设置是否进同一 UI。

## 10. Debug / tasks（以后）

- debug：VS Code debug view / console → board widget + editor；断点 / 变量 / 调用栈；需要 capability（sessions / threads / stack / evaluate）或 view。
- tasks：VS Code tasks view / output → board widget；DSH job 是另一条路径。
- **不进 MVP**；先记录。

## 11. 进程 / 状态 / 并发

- **进程**：PTY / SCM / search / diagnostics / output 都在 code server；client 只投影；进程 / 端口 / extension host 见 [tech-runtime](./2026-11-05-tech-runtime.md)。
- **状态**：VS Code 权威；prac 只拥有 window / board / active。
- **并发**：search cancel；terminal data stream；diagnostics settled；output backpressure；SCM action 串行。
- **多 workspace**：每个 workspace 一个 code server / capability 集；不共享。
- **失败**：code server 崩溃 → capability 重新订阅；PTY 退出 → session exited；search 失败 → error state。

## 12. Errors

| 错误 | 触发 | 处理 |
|---|---|---|
| `UNKNOWN_TERMINAL` | write / close 未知 session | reject |
| `TERMINAL_EXITED` | 已退出 | 显示 exitCode |
| `UNKNOWN_REPO` | SCM 动作未知 repo | reject |
| `SCM_CONFLICT` | commit 冲突 | 交给 VS Code |
| `SEARCH_CANCELLED` | cancel | 丢弃结果 |
| `SEARCH_FAILED` | 查询失败 | error state |
| `OUTPUT_TRUNCATED` | 超限 | 标记 / 保留尾部 |
| `UNKNOWN_CHANNEL` | show / clear 未知 | reject |

## 13. Testing

- **unit**：capability envelope、terminal session state、search cancel、SCM change mapping、diagnostics page。
- **L2**：capability → view / board / window；terminal data → xterm；search results → editor。
- **live**：containers / views / file / editor:group；terminal / SCM / search / output gate 为 planned。
- **planned**：terminal:open / scm:diff / search:query / problems:jump / output:channel。

## 14. Open

1. **terminal 归格**：app window vs panel widget；多 terminal identity。
2. **capability 形状**：terminal / SCM / search / output 是否都按同一 envelope；流式数据怎么走。
3. **SCM scope**：多仓库 / GitLens / conflict。
4. **search editor / 多根**：是否进 MVP。
5. **debug / tasks**：什么时候做。
6. **settings UI**：prac 自己的设置是否进 VS Code settings。
7. **output / 日志**：保留 / 清理 / 用户可见。
8. **并发**：search cancel / terminal data / output backpressure 的具体策略。
