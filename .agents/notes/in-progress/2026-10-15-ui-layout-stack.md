# Agent Note: stack 的行为定义

## Problem

一个区域可以**同时显示多条视图**（`stack` 模式），纵向排列，每条一行。这个"栈"是 prac 自己加的（上游把"多条视图上下排"实现为一个纵向的 `SplitView`，没有"栈"这个概念）。它的行为一直被分散地定：有些写在 layout note 的设计里，有些只存在于实现里，还有几处**互相冲突**——于是同一个动作在不同路径上给出不同结果（现场见过"布局里存 69、屏幕上画 519"）。

这份 note 只做一件事：**把栈的行为完整、可验证地定义下来**。先定行为，再选实现。

## 行为定义

按"人能观察到什么"写；每条都应当能被判据钉住。

### A. 构成

- **A1** 一个区域是否成栈，由区域名绑定决定（`stack: true`）。**只有可见视图 ≥2 时才真的成栈**；正好 1 条时**裸渲染**（无标题、无手柄）。
- **A2** 成栈时每条一行、同时可见；顺序 = 该区域的视图顺序。
- **A3** 每条有标题条（标题 + 折叠开关）与内容盒。

### B. 高度

- **B1** 默认**等分**可用高度。
- **B2** 人拖过之后，那一条的高度**就是它自己的**：屏幕上是它，刷新后仍是它。（这是"意图 vs 布局产物"的行为面：**行为上要求它稳定**，实现怎么达成另说。）
- **B3** 每条有**下界**（`MIN_ENTRY = 48`：标题 + 一点内容）。
- **B4** 折叠的条目占**标题高**（`HEADER_HEIGHT = 20`）。
- **B5** 上界：能被拖高到"**其余每条都还剩自己的下界**"为止——**任何一条都不会被压到 0**。
- **B6** 人设的高度加起来**超过**区域高度时：按比例收敛，且**任何一条不破下界**。
- **B7** **区域自身变高/变矮时**（窗口变化、邻居让位）：先按**比例**重分，**下界优先**。

### C. 拖动

- **C1** 手柄 = 条目的**底边** `SASH_SIZE`（5px）以内；**最后一条没有手柄**（它的底边就是区域的边）。
- **C2** 拖动只改**被拖那条与它下方的条目**；**绝不动它上方的**。
- **C3** 下方给不出空间时：**折下一条**（链式），而不是向上借、也不是停住——"连续折叠"。
- **C4** 链走完（下方全折叠）后：**再拖不动**。
- **C5** 一次拖动以**开始时的快照**为基准（不跨帧累积）。
- **C6** 松手后：屏幕上的值**成为**该条的高度（"屏幕 = 状态"）。
- **C7** 某条被挤到**它下界的一半**以下 ⇒ 那条**折叠**（阈值 = 半下界）；被拖那条自己过一半 ⇒ 折自己。
- **C8** 折叠**永不**被拖动反向触发——**展开只由人按折叠开关**。

### D. 折叠与展开

- **D1** 折叠 = 只剩标题；它的高度**被记住**（折叠那一刻的实测高度）。
- **D2** 展开 ⇒ 回到**记住的高度**；若记下的值不足下界，则丢弃该记忆、按分配取值。
- **D3** 折叠/展开对**其它条目**的影响，走 B7 的同一条规则（比例 + 下界）。

### E. 顺序

- **E1** 顺序 = 该区域的视图顺序。
- **E2** **不做**拖拽重排（今天没有；要做得单独裁）。

### F. 与「选择（tab）」的关系

- **F1** `stack` 与 `tabs` 是**同一批视图的两种模式**（由区域名绑定）。在 `tabs` 下同时只显示一个 ⇒ **没有高度语义**：该模式里各视图的 `size` **不生效**。

### G. 退化情形

- **G1** 0 条：区域不渲染（空区域不渲染）。
- **G2** 1 条：裸渲染。
- **G3** **全部折叠**：只剩一排标题——剩余空间归谁？见下面"必须先裁"。

### H. 持久化

- **H1** 每条的高度、折叠态、顺序都随布局持久化。
- **H2** 刷新后：**所见即所存**。

### I. 明确不做的

- **I1** 拖动**不**从上方借空间。
- **I2** 折叠**不**被拖动自动打开。
- **I3** 折叠的条目**不**被写尺寸（它是标题，不是"这么高"）。

## 必须先裁的三处

规则之间互斥，定了才能谈实现。

1. **总高固定 ⇒ 一条变，别的必变**：B2 与 B7/D3 在"区域高度不变、但人拖高一条"时冲突——下方条目要按 C2 让位（已定），但**当下方全折叠**、只剩上方可让时，与 C2 的"绝不动上方"直接矛盾。二选一：**(a)** 允许"上方让位，但只让到**自己的下界**"（C2 放宽为"不动上方的**人设尺寸**，但可作为最后手段被压到下界"）；**(b)** 保持"绝不动上方"，则此时**该条拖不动**（当前实现就是这条）。
2. **全部折叠时剩余空间归谁**（G3）：(a) 留白；(b) 按比例留在各条头上；(c) 最后一个标题贴到区域底部（"向下叠"）。
3. **顺序归谁**（E1）：保留"视图的属性"，还是"树的结构"——这一条直接决定实现选型。

## Alternatives（实现选型，待行为定案后再谈）

- **S1** 保留"视图记录存高度 + 渲染期分配"两个空间，把分配结果**写回**（试过，未收敛）。
- **S2** **栈 = 一个 `column` 分栏**：每条 = 一个只住一个视图的 region ⇒ 高度只剩树一个权威（与上游把 viewlet 做成 `SplitView` item 同形）。
- **S3** 高度**不持久化**，每次由策略算出；人拖出来的只存"偏好"（行为上 B2 会变成"建议"）。
