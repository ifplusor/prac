# Agent Note: stack 的行为定义

## Problem

一个区域可以**同时显示多条视图**（`stack` 模式），纵向排列，每条一行。这个"栈"是 prac 自己加的（上游把"多条视图上下排"实现为一个纵向的 `SplitView`，没有"栈"这个概念）。它的行为一直被分散地定：有些写在 layout note 的设计里，有些只存在于实现里，还有几处**互相冲突**——于是同一个动作在不同路径上给出不同结果（现场见过"布局里存 69、屏幕上画 519"）。

这份 note 只做一件事：**把栈的行为完整、可验证地定义下来**。先定行为，再选实现。

## 行为定义

按"人能观察到什么"写；每条都应当能被判据钉住。**对齐上游 `SplitView`**（`updateSashEnablement:1391-1420`、`distributeEmptySpace:1349-1355`），上游怎么做，这里就怎么写。

### A. 构成

- **A1** 一个区域是否成栈，由区域名绑定决定（`stack: true`）。**只有可见视图 ≥2 时才真的成栈**；正好 1 条时**裸渲染**（无标题、无手柄）。
- **A2** 成栈时每条一行、同时可见；顺序 = 该区域的视图顺序。
- **A3** 每条有标题条（标题 + 折叠开关）与内容盒。

### B. 边界与手柄（对齐 `updateSashEnablement`）

- **B1** 行与行之间有**边界**（一条 sash 的位置 = 上面那条的底边）。
- **B2** **一条边界可拖 ⟺ 它某一侧还有行能"缩"（`size − min > 0`）、另一侧还有行能"长"（`max − size > 0`）**。缩/长的判断是**累计**的：从边界往一侧看，只要**某一处**还能动，那一侧就算能动。
- **B3** **折叠的行不能缩也不能长**（它的 `size == min`、没有余量）⇒ 求高度时**跳过它**，继续向该侧找**展开的**行——"sash 邻着折叠的行，会继续向上下的展开的行求高度"。
- **B4** 两侧都找不到能动的行 ⇒ **边界禁用**（不可拖）。**上下两端连续折叠的行**因此不参与拖拽：有效的边界只出现在"还能动"的行之间。
- **B5** 手柄的可点区域 = 边界的 ±`SASH_SIZE`；**最后一条没有边界**（它的底边就是区域的边）。

### C. 高度

- **C1** 默认**等分**可用高度。
- **C2** 人拖过之后，那一条的高度**就是它自己的**：屏幕上是它，刷新后仍是它。
- **C3** 每条有**下界**（`MIN_ENTRY = 48`：标题 + 一点内容）与**上界**（见 C6）。
- **C4** 折叠的条目占**标题高**（`HEADER_HEIGHT = 20`）。
- **C5** 拖动按 B2/B3 的方向取高度：**先给离边界最近的、还能动的那条**（下方优先，照上游 `resize` 的顺序），到它的上界为止，再给下一条。
- **C6** **不按比例**：余量**整块给一个行**，到它的 `maximumSize` 为止（对齐 `distributeEmptySpace`）。**这条依赖"行有声明的上界"**——没有上界就会一条吞掉全部（现场见过 `openEditors` 从 69 被画成 519）。上界属于另一条 note：[../proposed/2026-10-15-ui-layout-grid.md](../proposed/2026-10-15-ui-layout-grid.md)。
- **C7** 人设的高度加起来**超过**区域高度时：按 C6 的顺序收敛，且**任何一条不破下界**。
- **C8** **区域自身变高/变矮时**（窗口变化、邻居让位）：走 C5/C6 的同一条规则（按顺序、到上界为止），**不按比例**。

### D. 拖动的手势

- **D1** 一次拖动以**开始时的快照**为基准（不跨帧累积）。
- **D2** 松手后：屏幕上的值**成为**该条的高度（"屏幕 = 状态"）。
- **D3** 某条被挤到**它下界的一半**以下 ⇒ 那条**折叠**（阈值 = 半下界）；被拖那条自己过一半 ⇒ 折自己。
- **D4** **连续折叠**：一条折起来之后，边界按 B3 继续向该侧找下一个展开的行 ⇒ 一次拖动可以连着折起若干条。
- **D5** 折叠**永不**被拖动反向触发——**展开只由人按折叠开关**。

### E. 折叠与展开

- **E1** 折叠 = 只剩标题；它的高度**被记住**（折叠那一刻的实测高度）。
- **E2** 展开 ⇒ 回到**记住的高度**；若记下的值不足下界，则丢弃该记忆、按分配取值。
- **E3** 折叠/展开腾出或需要的空间，走 C5/C6 的规则（给还能长的行、到上界为止、**不按比例**）。

### F. 顺序与重排

**移动的模型**对齐上游 `Grid`：给定**参照行 + 方向**（上/下）即可确定落点（`moveView(view, sizing, referenceView, direction)`，`grid.ts:480-495`；方向 `Direction.Up/Down`，`editorPart.ts:807-810`）。同一父节点内是**纯换序**；被移动的视图**保持自己的尺寸**（不传 `Sizing` 时不做重新分配）。

**拖动的手势（已定）**：**推的是 sash**（行与行之间的那条边界），不是标题条。**折叠的行也能被推**。

- **F1** 顺序 = 该区域的视图顺序。
- **F2** **重排的抓手是 sash**（边界）；落点同样由 sash 表达——把一行推过某条边界，它就落到那条边界的另一侧（等价于"参照行 + 方向"）。
- **F3** **折叠的行也能被推**（它只是一个标题条 + 它的高度是被记住的）。
- **F4** 拖动**只改顺序**：**每条的高度跟着它自己走**（不留在槽位上），折叠与否也跟它自己走。
- **F5** 重排**不折叠、不展开**任何行：它**不触发** B/C/D 那套 snap——两种手势互不触发。
- **F6** 范围是**同一区域内**；把视图搬到别的区域走既有的"在区域之间搬视图"。
- **F7** `tabs` 模式下同一份顺序就是 **tab 的顺序**，重排同样成立（顺序是区域级的，两种模式共用）。
- **F8** 取消（丢到区域外、或 Esc）⇒ **回到原位**，不留改动。
- **F9** 重排后的顺序随布局持久化。

**上游对照**：`Grid` **没有内置拖拽**（`gridview.ts` 里没有 `dragAndDrop` / `dropTarget`），移动是程序化的；拖拽手势在更高层（编辑器的 tab DnD、侧栏的 viewlet DnD），那两处不在这棵裁剪过的源码树里 ⇒ "推 sash"这条是**prac 自己的决定**，不是照抄。

### G. 与「选择（tab）」的关系

- **G1** `stack` 与 `tabs` 是**同一批视图的两种模式**（由区域名绑定）。在 `tabs` 下同时只显示一个 ⇒ **没有高度语义**：该模式里各视图的 `size` **不生效**。

### H. 退化情形

- **H1** 0 条：区域不渲染（空区域不渲染）。
- **H2** 1 条：裸渲染。
- **H3** **全部折叠**：没有人能长 ⇒ 腾出的空间**留白**（推导自 B2/B4：此时所有边界都禁用）。这条是**从上游规则推导**的，不是直接观察。

### I. 持久化

- **I1** 每条的高度、折叠态、顺序都随布局持久化。
- **I2** 刷新后：**所见即所存**。

### J. 明确不做的

- **J1** 拖动**不**从"不能动的那一侧"借空间（那一侧要么是折叠的行、要么已经在它的下界）。
- **J2** 折叠**不**被拖动自动打开。
- **J3** 折叠的条目**不**被写尺寸（它是标题，不是"这么高"）。
- **J4** 分配**不按比例**（C6）。

## 必须先裁的

1. **行的上界给多少**：C5/C6 与"不按比例"都以"行有 `maximumSize`"为前提，而 prac 现在没有 `max`。没有它就只能回到"按比例"（我们试过 A″）或者"一条吞掉全部"（现场见过 519）。⇒ 需要裁：`max` 从哪来（缺省值 / 逐视图声明 / 由区域高度与其它行的下界推出）。
2. **顺序怎么表示**：行为上已定（F1–F10：顺序是区域里的**数据**、可被拖拽改写、跟着视图走）。剩下的是表示形式——留在视图记录里，还是变成树的结构（F1 的顺序 = branch 的孩子顺序）——这仍属于实现选型。
3. **E1 记的是哪一刻的高度**：折叠那一刻的实测值，还是**拖动开始时**的值（上游 `snapAfter.size` 取的是后者）。

## Alternatives（实现选型，待行为定案后再谈）

- **S1** 保留"视图记录存高度 + 渲染期分配"两个空间，把分配结果**写回**（试过，未收敛）。
- **S2** **栈 = 一个 `column` 分栏**：每条 = 一个只住一个视图的 region ⇒ 高度只剩树一个权威（与上游把 viewlet 做成 `SplitView` item 同形）。
- **S3** 高度**不持久化**，每次由策略算出；人拖出来的只存"偏好"（行为上 B2 会变成"建议"）。

## Open questions

- 上面"必须先裁"的三处。
- **sash 上两种手势如何共存**（推它 = 重排，拖它 = 改高度）：需要一个明确判定，例如——**同一条 sash：拖到"超过阈值"才变成重排**；或**上下半区/加修饰键**分工；或补一个独立的抓手元素（上游 sash 本身是独立元素，`splitview.ts:1168-1173`）。这条定了才能实现。
- 重排的视觉反馈细节（插入线样式与阈值）；双击标题条是否折叠；重排是否有键盘路径（如 Alt+↑/↓）。
- `tabs` 与 `stack` 之间切换时，各自的尺寸怎么处理（F1 只说 `tabs` 下不生效）。
