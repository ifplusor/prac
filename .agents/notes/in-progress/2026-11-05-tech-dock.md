# Technical dock — pins, intent, running, active

> app 模型见 [tech-app](./2026-11-05-tech-app.md)；窗口系统见 [tech-ui](./2026-11-05-tech-ui.md)；board 见 [tech-widget](./2026-11-05-tech-widget.md)。

## 1. 覆盖与边界

dock 是**外壳表面**（像 activity bar），消费 app 与 board，不定义它们。它拥有的是 **pins**：哪些快捷方式被固定、按什么顺序、指向哪个 app + 参数。

**本 note 覆盖**：pin / unpin / restore、intent 参数、running / active 的读取、拖拽到 dock、overflow、持久化 key。

**不在本 note**：app 的启动与实例 → [tech-app](./2026-11-05-tech-app.md)；board 的编排 → [tech-widget](./2026-11-05-tech-widget.md)；窗口的激活 → [tech-ui](./2026-11-05-tech-ui.md)。

## 2. 数据模型

### 2.1 `pracDock`

dock 是 shell 组件（像 macOS 的 Dock / Windows 的任务栏），拥有自己的 pin 列表：

```ts
interface PracDockItem {
  id: string;
  appId: string;
  params?: unknown;       // 启动参数（boardId 等）
  instanceId?: string;    // 上次启动的实例
}

interface PracDock {
  list(): readonly PracDockItem[];
  pin(item: PracDockItem): void;
  unpin(id: string): void;
  subscribe(listener: () => void): () => void;
}
```

- 只存 **pins** 与持久化（`prac-dock/v1`）；
- 不存 running / active：running 来自 `pracAppInstances`，active 来自 WM；
- 点击：`instanceId` 有效 → `activateWindow`；否则 `openApp`；
- 三种状态合成在 dock 的 `items()` 里：pins + running + active。

### 2.2 pin 的生命周期

| 事件 | 结果 |
| --- | --- |
| `pin(item)` | 加入 pins，持久化 |
| `unpin(id)` | 从 pins 移除，持久化；**不影响 board、widget、窗口** |
| 关闭 board 窗口 | pin 不变 |
| drag 到 dock | `pin(item)`，带拖入的 board |
| 实例退出 | `instanceId` 失效，pin 保留（下次点击重新启动） |

- unpin ≠ 关闭：board 仍在，仍可由其它入口打开；
- restore = `pin` 一条已存在的 board。

## 3. 点击语义

```
click(pin)
  → instances.get(pin.instanceId)
      ├─ 命中 → activateWindow(instance.windows[0])   // reopen
      └─ 未命中 → applications.launch(pin.appId, pin.params)
                    → pin({ ...pin, instanceId: created.id })
```

- pin 是 **intent**（`appId` + `params`），不是实例句柄；
- 但 pin **记住自己启动的实例**（`instanceId`），因为同一 `(appId, params)` 可以合法地有多个实例（同一文件在两个 window group）；
- 其它入口打开的实例不归 dock 管。

## 4. running / active

| 状态 | 来源 |
| --- | --- |
| running | `instances.get(pin.instanceId) !== undefined` |
| active | WM 的焦点窗口属于该实例，或该 board 的 container 是 region 的 active child |

dock 只读，不写窗口状态。

## 5. 拖拽

- widget 拖到 dock 图标 → 打开该 board 并 move 进去；
- widget 拖到 dock 空白 → 新建 board window 再 move（提交时才创建，失败回滚）；
- 取消 → 删除本次新建的空 board。

## 6. 持久化

- key：`prac-dock/v1`；
- 内容：pins（`id` / `appId` / `label` / `side` / `params` / `instanceId`）、顺序；
- `instanceId` 可以过期，读不到实例时视为未运行（heal）。

## 7. Open

1. **overflow**：pin 很多时的滚动 / 分组；
2. **跨 Space**：dock 是全局还是 per-Space；
3. **dock 与 activity bar 是否同一个表面**（当前左 dock 兼作 activity bar）；
4. **unpin 后如何 restore**：命令面板 / 右键菜单 / board 的 "Pin" 动作。
