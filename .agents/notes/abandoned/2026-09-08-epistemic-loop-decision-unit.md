# Agent Note: 认识论循环 + 决策交付单元

## Problem

软件开发是创造性工作，没有重复的日常事务性内容；工作方式是「边做边想、不断调整」，很难在一开始把所有东西想清楚再开干。

与此同时，agent 设计不好架构、爱走捷径。这主要不是能力问题，而是**框架与后果**问题：agent 是目标导向的——忠实于「把这个任务完成」；而架构是一种**价值**（对未来的约束：为了以后能持续演进，现在宁可少做）。当目标与价值冲突时，agent 会朝目标最省力的路径走，因为价值没有被显式加载、也没有牙齿。而且 harness 给 agent 的框架是「当前任务」，不是「整个系统」；它从不把系统长期健康装进视野，也从不曾让 agent 承担自己决策的后果——每次调用都是全新头脑。

## Proposal

- 以**认识论循环**（决定 → 验证 → 重审）为主模型，而不是生产线（计划 → 执行 → 交付）。计划是**活的假设**，会随现实揭示而不断被推翻重修。
- **agent 的交付单元是「决策」，不是「代码」**：交出来的是「有几个选项、各自代价、我推荐哪个、我打算怎么验证」，代码只是副产品。
- **人的交付单元是「承诺」**：把候选决策变成承诺的那份判断，以及系统的结构。
- **责任永远在人**：软件是对世界（和对未来维护者、对自己未来）的承诺，agent 担不起。但 harness 的职责是让「你的责任」变得**可行使**（暴露推理、可验证、可回滚），而非可甩脱。
- **认识论 harness 的六件事**：决策优先、依据一等公民、可逆带检查点、审查是主界面、架构记忆、活的计划。

## Alternatives considered

- **生产线模型（计划 → 执行 → 交付）**：把「人的思考触发」当成链路里要消掉的延迟；但对一个边做边想的人来说，**那恰是价值本身**，不是等待时间。
- **「agent 自主长程」**：为一种不同的工作（推进）优化，与「边做边想、深度人类参与」冲突。
- **「让 agent 直接改文件」**：把这套 rig 的产物坍缩成 diff，人被迫在结果里找 bug（贵、低杠杆），而不是在决策层面与之对话（便宜、高杠杆）。

## Open questions

- 架构记忆里，agent 到底装载多少、以什么形式装载，才能让捷径没有立足之地。
- 长程任务的「探索」（拓宽选项）与「承诺」（收敛到对的东西）边界在哪儿。
