# UI — OS-like Space（project folder-scoped）

## Summary

prac 的根是 **project folder**：文件、notes、git、conversation、background service、Space 都挂在它上面。UI 是 project folder 范围内的 **OS-like 工作台**：

- 两侧是 **dock**：rail/launcher + 内容 **sidebar**；
- **panel** 是快速唤出 / 收起的 panel；
- 中央 **stage** 是屏幕区域；
- **application** 打开 **window**，window 放进 **window group**；
- stage 由 window group 组成，可以 split；**Space** 是命名的 stage 布局。

**Space 是 prac 的核心概念、主线**。默认只有一个 Space；其他 Space 按需创建（像 macOS Spaces）；同一 project folder、同一 conversation、同一批文件可以出现在不同 Space，只是布局 / active window / panel 不同。

## Motivation

窗口布局需要自由：

- application 打开成 window，window 放进 window group；
- window group 可以 split；
- Space 按需创建；
- 固定「editor 中心 + background service 右侧」或固定「background service 中心 + editor 旁边」都只覆盖一半。

同时，UI 服务于人，不服务于 agent：

- 人需要随时看 chat、文件和 review，而不是被固定在某个协作布局里；
- agent 是工作在 prac 里的运行时；chat 是一个 application，不是整个 UI；
- 人应当能关闭 chat / 把 background service 收到后台，仍然正常改文件、看 review。

## 1. 对象

| 对象 | 是什么 |
|---|---|
| **Project folder** | 根上下文；文件、notes、git、conversation、background service、Space 的作用域 |
| **Application** | 启动身份；editor / chat / diff / GitLens / terminal / plan note 等；window 由 app 打开 |
| **Window** | app 的实例：一个 editor 文件、一个 chat、一个 diff、一个 terminal；stage 的 tab 单位 |
| **Widget board** | 摆放 widget 的布局面；Explorer / SCM / GitLens 是 board；sidebar / panel 里直接是 board，stage 上由 widget window 承载 |
| **Widget** | board 内部的可组合单元：Folders / Open Editors / Outline / Timeline / Changes…；可以移动 |
| **Window group** | tile mode 的 windows 容器；默认一个；split 才多个 |
| **Tab** | window group 里指向一个 window 的 label |
| **Space** | 虚拟桌面；默认一个；按需创建；有 Stage / panel / active window 状态 |
| **Stage** | 屏幕区域；window group 的布局 |
| **Dock** | 侧区的 rail + launcher；内容面是 **Sidebar**（承载 widget board） |
| **Sidebar** | dock 的内容面；承载 widget board（Explorer / SCM / GitLens） |
| **Panel** | 快速 side panel；承载 widget board |

### 关键边界

- **window 从 app 打开**，没有无主 window；
- **tab 是 window，不是 widget**；
- **widget 不直接进 window group**；widget 在 board 里；
- **widget board 不是 app，也不是 window**；sidebar / panel 里直接是 board；dock 的 rail 只是 launcher，内容面是 sidebar；stage 上由 widget window 承载；
- 同一个 app 可以 single / multi；editor / diff / terminal multi，chat / GitLens single；
- editor window = 一个文件；
- editor group 不是 prac 概念；window group 取代它。

## 2. Applications 与 placement

- Application 可以 **pin**（dock rail）、**open**（sidebar / panel board）、**stage**（application window / widget window）；
- 同一 application 可以在这些形态之间移动；
- 默认：
  - Explorer / Search / SCM / GitLens 在左 / 右 sidebar（dock 的内容面）；
  - Chat / Editor / Diff 在 stage；
  - GitLens 可 panel board 也可 stage widget window；
- dock 的 rail 是 launcher；dock 的内容是 sidebar（board），不是窗口内容；
- application registry 归一化 VS Code / DSH 来源；default placement、order、pin 状态；
- 用户移动后持久化；插件不硬编码最终位置。

## 3. Stage / window groups

- **active window group + 0..N inactive window groups**；active 是主位；
- 文件打开：在 window group 里新增 / select 一个 editor window（一个文件）；
- chat 是同一 window group 的另一 window（single-instance）；
- split 才产生第二个 window group；
- window group 的 tabs 是 windows；只显示一个 active window；
- window 内部视觉（文件内容 / conversation / diff）不归 window group 管；
- window group 可以 maximize / split / close / move；active window group 关闭后下一个接管；
- 同一文件可以出现在多个 window group / Space（多个 editor windows）；
- Space 是 window group 的排列，不是 window group 内部 tab。

## 4. Widget / board

- Explorer / SCM / GitLens 是 **widget board**；board 内部是 widget stack；
- Timeline / Outline / Folders / Changes 是 **widget**，可以在兼容 board 之间移动；
- 单 widget board 是合法的；不是特殊 app / window；
- widget board 放到 stage 时由 **widget window** 承载；window group 的 tab 是 widget window，不是 widget；
- widget header / actions 属于 board / widget；window group tab strip 的 actions 属于 active window；
- widget 的 source 与 board 的 owner 是两件事；board 可以接收 foreign widget。

## 5. Spaces

- 默认一个 Space；按需创建；
- 每个 Space 保存 window group / active window / panel / board 状态；
- Space 按 project folder 存储（对齐 VS Code 的 workspace storage）：每个 project folder 一套；切到别的 project folder 不串 Space；
- 同一 conversation / 文件跨 Space；多个 window 实例共享内容；
- Space 切换恢复布局；
- Space 是布局容器，不是第二个 project folder；
- project folder 切换时，旧 Space 状态保留；切回恢复。

## 6. Background service 侧

- 只组合 DSH 已支持的 conversation / chat / turns / tool calls / status；
- plan 是 note（人和 background service 共编）；
- review 是 diff / chat；
- plan mode / DSH plan review 不是这条路；
- tool approval 是 ui-approval 内置的 allow / reject；
- takeover 是 human edit；revert 是 git；checks 是 shell / tool calls；
- 不新增 plan application / review application / checkpoint / takeover 对象。

## 7. Human freedom

- 默认 Space 可以没有 background service（chat 收起 / 后台）；
- chat application 可以关闭 / 收 panel；
- 通知不抢焦点；
- 人可以直接改文件、看 review、跑命令，不依赖 chat 在场；
- 人可以把 chat / 文件 / review 放在任意 window group / Space。

## 8. Plugin / contribution model

- VS Code / DSH 都映射成 application / window / widget；
- application registry 归一化；
- default placement、header、actions、pin 状态；
- 用户移动后持久化；
- 插件不硬编码最终位置；
- window / widget 的 source 与 owner 分离；移动只改 placement，不改 source。

## 9. Layout / geometry

基准分辨率：1600 / 1280 / 768。

- 1600：active window group + inactive window group；panel 可开；
- 1280：panel 更窄；inactive 仍可并排；
- 768：stage 仍 active + inactive，但 inactive 以 drawer / overlay 出现；panels 收起；dock rail 40 / 36；Space switcher 保留；
- 没有 Space-level tab bar；
- window group 的 tab strip 只显示 windows；
- sidebar / panel 的 board 不使用 window group tab strip。

## 10. Decisions

- Space 是核心；默认一个，按需创建。
- OS-like：dock / panel / stage / window group / Space。
- Application 是启动身份；window 由 app 打开。
- window group 的 tabs 是 windows；widget 不是 tab。
- Explorer / SCM / GitLens 是 widget board；Timeline / Outline / Folders 等是 widget，可移动。
- widget board 放到 stage 时由 widget window 承载。
- editor window = 一个文件；editor group 不再是 prac 概念。
- background service 侧只组合 DSH 支持的 conversation / chat / status；不新增 plan / review application 等对象。
- 默认 Space 可以没有 background service；chat 可关闭 / 后台；通知不抢焦点。
- Space 按 project folder（workspace）存储，不是 origin 全局；对齐 VS Code 的 workspace storage。
- tile mode 是唯一模式；free window 当前不考虑。
- Dock = rail/launcher + sidebar 内容；sidebar 是 dock 的内容面；panel 是快速 panel。

## 11. Open questions

1. Window group 的默认交互：active / inactive、maximize、tab move、键盘；同一 window 能否跨 window group。
2. Panel 默认：左 Explorer 开、右收、bottom 收；是否更激进 auto-hide；768 drawer。
3. Space 状态：默认一个；按需创建 / 增删；window 状态跨 Space 保留的范围（作用域已定：按 project folder）。
4. Application / widget model：default placement、pin、header / actions 的规则。
5. Note 共编：人 / background service 共编的可见性、冲突、版本。
6. 人的自由：chat 关闭后如何恢复；通知强度。
7. First-run：最近 project folder / 打开文件夹入口；空 project folder 的 next step。
8. Plugin：application registry / default placement / pin；widget / board 的扩展点；theme / trust。

## 12. Validation

- **First-run**：没有 project folder → 选择入口；选择后 → 工作台；空 project folder 的 next step。
- **Project folder**：文件树 / notes / git / conversation / background service / Space 跟着 project folder；切换 project folder 换工作台；background service 的 cwd 是 project folder。
- **Spaces**：默认一个；按需创建；切换；每个 Space 的 window group / active window / panel 状态保留；同一 conversation / 文件跨 Space；background service 后台继续；Space 按 project folder 存储，切到别的 project folder 不串；切回恢复。
- **Applications / panels / docks**：Explorer / SCM / GitLens 在 sidebar / panel board；Chat / Editor / Diff 在 stage；dock rail 常显、点击切 sidebar；panel 快速唤出 / 收起；768 drawer。
- **Stage / windows**：打开文件 → editor active window group，chat 是 inactive window；看 chat → chat active，文件是 inactive；maximize / split / tabs。
- **Widget / board**：Explorer / SCM 是 board；Timeline 可在 board 之间移动；widget 不成为 window group tab；单 widget board 合法。
- **Background service 侧**：plan note / editor / note 机制；tool approval；diff / checks；human edit；git revert；只呈现 DSH 支持的 status / cancel。
- **Human freedom**：默认 Space 无 background service / chat 收起；chat application 关闭 / 后台；通知不抢焦点。
- **Plugins**：VS Code 与 DSH 的 application 共存；pin / panel / stage；布局持久化。
- **1600 / 1280 / 768**：stage active + inactive；panel 开合；drawer；无 console error。
