# Agent Note: 决策空间如何呈现（立身之本，开放）

## Problem

agent 现在把「做决策的空间」直接坍缩成「改文件」，人被迫在**结果里**找 bug。要把「审决策」而不是「审 diff」做成常态交互——这被认为是这套工具的**立身之本**。

## Proposal（正在探索，未定案）

- 一个**候选决策**用什么结构承载？（选项、代价、推荐、验证计划）
- 什么时机摊开：一次性全摊，还是逐层展开？
- 怎么避免变成「填表式追问」（对话式、自然，而非表单——见 dual_agent_architecture 里 Secretary 明确反对的坏对话）。
- 人用什么直觉判别一个候选决策该不该采纳？是信号可被显式化（可读、可复述的维度），还是本质上是**整体性、一望即觉**？

> 后者更可能：人的判断是一眼的东西，harness 的价值是把「该触发判断的时刻」和「让判断容易做出的上下文」给到位，而不是逼人把判断写成可复述的规则。

## Alternatives considered

- **「把人减到只在关键时刻出现」**：吸引人（减少监督负担），但容易漏掉真需要人的事。怎样的打断是**对的分歧点**、在**对的时机**出现，目前基本没有好答案。
- **「完全不打断、完全放权」**：责任真空，信任膨胀到远超实际核验。

## Acceptance criteria

能把「审决策」做成常态交互，且代价低、杠杆高；不该打断时不打断，该打断时不漏。
